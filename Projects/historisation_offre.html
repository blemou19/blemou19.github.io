Intégration &
Historisation des Offres

Système d'intégration automatisée de fichiers CSV journaliers en SQL Server avec table de staging, historisation des offres par SCD Type 2, contrôles de cohérence, journalisation des traitements et sécurisation par contraintes et index. Conçu comme un flux batch réel en environnement professionnel.

100% Idempotent
SQL Server (T-SQL) BULK INSERT Staging Table SCD Type 2 ProcessLog Cursor Index unique TRY/CATCH

Contexte & objectif

Ce projet simule un flux d'intégration batch quotidien en environnement professionnel : chaque jour, un fichier CSV nommé DATA_YYYYMMDD.csv est importé, nettoyé et intégré dans une base de données SQL Server.

L'enjeu principal est l'historisation des offres commerciales — chaque changement de prix, disparition ou fermeture de magasin doit être tracé avec une date de début et de fin de validité (principe du Slowly Changing Dimension Type 2). Un système de log (ProcessLog) garantit la traçabilité et l'idempotence des traitements.

Pipeline de traitement

📂 CSV Journalier DATA_YYYYMMDD.csv
→
🗂️ Staging BULK INSERT + nettoyage
→
⚙️ Traitement 3 cas métiers
→
🗄️ Offer (SCD2) PeriodStart / PeriodEnd
→
📋 ProcessLog SUCCESS / ERROR

Modèle de données

La table centrale dbo.Offer implémente le pattern SCD Type 2 :

ColonneTypeRôle
NumberIDINTIdentifiant unique de l'offre
StoreNumberIDINTIdentifiant du magasin
EANBIGINTCode article
PriceMONEYPrix appliqué
PeriodStartDATETIMEDébut de validité
PeriodEndDATETIMEFin de validité — 9999-12-31 = offre active
VerifiedDateDATETIMEDernière date de présence dans un fichier

3 cas métiers gérés automatiquement

CAS 01
Prix modifié

L'offre active est clôturée (PeriodEnd = @FileDate) et une nouvelle offre est créée avec le nouveau prix.

CAS 02
Article absent du relevé

Une offre active non présente dans le fichier du jour est automatiquement clôturée — l'article n'est plus proposé.

CAS 03
Magasin fermé

Toutes les offres actives d'un magasin dont la closingdate est atteinte sont clôturées en une seule opération.

Extrait de code — Nettoyage & contrôle qualité

/* 1) IMPORT STAGING */
TRUNCATE TABLE dbo.Staging_Price;

BULK INSERT dbo.Staging_Price
FROM 'C:\DATA20241104.csv'
WITH (FIRSTROW = 2, FIELDTERMINATOR = ';', TABLOCK);

/* 2) NETTOYAGE — rejet des prix invalides */
DELETE FROM dbo.Staging_Price
WHERE AppliedPrice <= 0 OR RecommendedPrice <= 0;

DELETE FROM dbo.Staging_Price
WHERE AppliedPrice > 1000 OR RecommendedPrice > 1000;

/* 3) LOG — traçabilité complète */
INSERT INTO dbo.ProcessLog (
    FileName, FileDate, ImportedRows, RejectedRows,
    CreatedOffers, UpdatedOffers, Status
)
VALUES (@file, @FileDate, @ImportedRows,
        @RejectedRows, @CreatedOffers, @UpdatedOffers, 'SUCCESS');

Sécurisation & idempotence

Le système est conçu pour être relancé en toute sécurité :

  • Un fichier déjà traité en SUCCESS est automatiquement ignoré (skip)
  • Un index unique sur (StoreNumberID, EAN) où PeriodEnd = 9999-12-31 garantit qu'une seule offre active par article/magasin
  • Chaque fichier est traité dans un bloc TRY/CATCH — une erreur sur un fichier n'interrompt pas le traitement des suivants
  • La Version 2 traite plusieurs fichiers en boucle (cursor) avec gestion d'état par fichier
